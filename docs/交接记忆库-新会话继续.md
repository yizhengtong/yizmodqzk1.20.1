## 三、当前架构（已实现，全部在 yizmodqzk）

### 攻击链路（EntityASMUtil.applyProportionalDreamDamage）
```
攻击命中 → TotalHealthOverride.apply(attacker, target, dream)   ← 主路径（通用管道）
   ├─ 清 DREAM_ACCUM + 重置 delta 通道为 0（关键！防 agent 读值与存储不一致）
   ├─ judge：读当前逻辑血（主槽存储解码优先，免疫 agent/delta）
   ├─ modify：主槽写目标 + 全部「≈当前血」镜像同步写 + 门控击穿 + 目标≤0 走正常死亡
   └─ GateHunt：2 tick 写回验证，被拉回则行为猎杀权威门控
失败才走旧链路（藏血Map/差值/判死标记/定位器/1b/delta 软压）
```

### 关键类（`src/main/java/net/minecraft/client/yiz/tool/health/`）
| 类 | 职责 |
|---|---|
| `EntityHealthLocator` | 槽位行为定位（field/accessor/naccessor/string/codec），负缓存，JSON 持久化；`readLocated(codec)` = **存储解码**（免疫 agent）；支持声明式槽 `declareSlot` + string inverse（meta `b=上限;inverse=true`） |

## 四、三目标实体结论（全部已逆向确认）

### 1. 基岩傀儡 BedrockGuardian（Mbt）
- 真血 = `1000 − descramble(encAcc)`，`encAcc = intBitsToFloat(rawInt(plain) ^ 0x5A45A1F0)`（KEY=1513910768，BOSSMX=1000）；`encLastAcc` 为镜像（regen 会使其与 encAcc 差 1）
- `setHealth/heal` 空实现；`die/remove/setRemoved` 在 `mobiaton_debug=false` 时全拦截；tick 里 `plain≥999 → mobiatonDebugger+discard` 是**原生移除**；`getMaxHealth()` 被换成 KBR(=1.0) → vanilla 通道是显示通道（缩放 health/1000）
- **看门狗**：`ForgeEventHandlers.MbtTicks.guardHealth` 每 level tick 用 Unsafe 读 encAcc、读 getHealth 推断 plain，不一致就重置 encAcc=expected(0)=满血；`guardOne` 复活被移除的守卫并 reRegister
- 已解决：codec 槽命中（key 正确）、首次命中精确；**「每次命中只掉1血」根因 = 残留 delta=-inf 使 agent 包装的 getHealth ≠ 存储真值 → 看门狗判定篡改拉回**（修复：管道执行前/死亡后重置 delta，部署于 `c4b08954`，**待用户验证**）
- 遗留：看门狗复活（guardOne+reRegister）会让击杀后的守卫回满血复活——要处理需动其 WATCHED 表（模组侧）或持续反注册（用户否决每 tick），可讨论

### 2. 路西法 LuciferEntity（scourge，MCreator SRG）
- 真血 = Integer DataParameter `DATA_ERealHealth`（初始1000）；`getHealth()` 直接返回它；`setHealth` 只允许加血
- `LuciferDefenseProcedure` 每 tick（EReady=true 时）强制：扣血上限 50/tick（`lucifer_health2` 参考值比对）、**血线下限 10**（`Math.max(n,10)`）、慢回血；`remove()` 空实现 + 每 tick `dead=false` + revive
- 已解决：naccessor 槽命中，通道可写；**纯减法需打穿防御门**——`GateHunt` 可行为猎杀（EReady 是 NBT 布尔），或声明式：`health_overrides.json → gates: {"net.mcreator.scourge.entity.LuciferEntity":[{"kind":"nbt","name":"EReady","value":false}]}`
- 死亡流程：ERealHealth=0 + EReady=false 后 vanilla 死亡链可走（dropAllDeathLoot）；模组专属掉落（HALO_OF_SINS，ETProcedure 状态机）属 P2

### 3. 无名术士 NamelessWizardsEntity（iss_csw）
- 真血 = String DataParameter `DATA_EXISTENCE`（`"HEC"+float`，existence=已受伤害，health = maxhealth − existence，maxhealth≈1000）
- `getHealth()` 不读 existence（返回常量/阶段推导）→ **行为探测无法自动定位** → 需声明式槽：
  `health_overrides.json → slots: {"org.xszb.interlace_spellweaves.entity.boss.nameless_wizards.NamelessWizardsEntity":{"kind":"string","field":"DATA_EXISTENCE","inverse":true,"meta":"b=1000"}}`
  （EntityHealthLocator 已支持 string inverse；**未实测**）
- 门控：`canDie`(NOTDIE 布尔，默认 false)/`canKill`/反作弊(YOU_CHEAT)；`remove()` 被门控时进反作弊；死亡走 ActType 相位状态机（P1/P2 范围）

## 七、代码纪律（用户反复强调）

- **不要针对**：代码里零类名/字段名硬编码；行为探测 + 声明式配置（health_overrides.json）是唯一例外出口
