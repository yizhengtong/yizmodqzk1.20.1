## 四、四个目标实体的状态

### 1. 基岩傀儡 / 合金守卫（Mbt_test_only）—— ✅ 已解决（直接减法通了）

- 真实血量在**外部单例** `AuthorityStation.CACHE`（`Map<UUID, Entry>`），`Entry.accCipher` 是 `CipherHelper$Mci` 加密对象。
- **破解要点**：
  1. `ExternalHealthStore` 下钻找到密码载体（char+float+int 三字段对象）；
  2. ARX 密码反解：`fwd(x)=rotateLeft(reverse(x)-ROUND,17)`、`inv=reverse(rotateRight(x,17)+ROUND)`，**ROUND=+1640531527**（0x61C88647，是 -0x9E3779B9 的补码，**不是负的 0x9E3779B9**，符号写错会导致 decode 出乱码、血只掉零点几）；
  3. 写所有密码字段（accCipher/lastCipher 都写，防字段序歧义）；
  4. `accCipher` 为 null（未受伤）时用 `Unsafe.allocateInstance` 分配新密码对象。
- **实测结果**：血 1000→990→964→…稳定递减，`[ExtStore]` 命中，`[TotalOverride]` 每击精确减法。

### 2. 路西法（scourge，但被 Mbt 壳包裹）—— ⚠️ 逆向完成，未攻克

- 实际实体类是 `Mobiaton.mobiaton_01.Utils.HiddenShell$LuciferEntity`（Mbt 的 **KlassShell 换壳机制**：用 Unsafe 把任意非守卫实体的 class 指针换成生成的壳类）。
- **四层防御**（反编译已确认）：
  1. `LuciferHurtProcedure`（LivingHurtEvent，门控 `EInvulnerableTime==0`）：单次伤害压到 `damage_cap×最大血`(≈50)，并直接写 `ERealHealth=当前−real_amount`；
  2. `LuciferDefenseProcedure`（每 tick，门控 `EReady`）：按全局参考值扣血上限 50/tick + 血线下限 10 + 回血；
  3. **`lucifer_health2`（`ScourgeModVariables.WorldVariables` 世界级存档数据里的 double）**：两层限伤都用它当参考值——**这是关键，它不是实体身上的字段/NBT**；
  4. `LuciferETProcedure`+`LuciferCheckProcedure`：EDeath 状态机 0→1→2→3→4 + 掉落。
- **已证伪**：EReady 翻转能持久（`候选2tick后=false`），但血仍被拉回——说明**限伤门是全局 `lucifer_health2`，GateHunt 在实体身上猎不到**。
- **下一步**：需要新增「**外部全局变量猎杀**」（找 `Level` saved data / capability 里存 double 且与血量强相关的对象，行为探测「写它→血能钉住」）。这是 S9 之外的新形态，P2 难度。

### 3. 无名术士（iss_csw）—— 待验证（P1 状态机播种）

### 4. giantwarden（巨型坚守者）—— 未做（最硬）

## 五、本会话已修复的关键 bug（重要）

1. **`HealthModificationScheduler`：一次性任务执行后未从列表移除** → `remainingTicks` 停 0，每个 tick 重复触发。日志表现为门控猎杀所有候选挤在同一毫秒疯狂循环。已修：执行后 `tasks.remove(task)`。
2. **ARX 轮常数符号**：必须 `+1640531527`，写负号会导致 encode/decode 与模组互逆失败（血只掉零点几）。
3. **GateHunt 三处提前返回**：`target>0`（中段伤害不猎）、`isDeadOrDying`（复活型漏猎）都去掉；仅「血向上拉回」才触发猎杀（避免误猎并发伤害）。
4. **写密码字段只写一个**：改为写全部密码字段（字段序不可靠）。
